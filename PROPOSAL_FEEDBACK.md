# Project Proposal Feedback

The project is clearly described and well motivated, and the two main questions (how accurately the winner can be predicted at 5, 10, and 15 minutes, and which early features matter most) are specific and easy to follow. Strong points include the match-level split, the plan for a chronological split, keeping the final test set untouched, storing raw data separately from processed data, the fallback plan, and the note that the results are associations rather than causation. To strengthen the proposal, please name the evaluation metrics (for example accuracy, ROC-AUC, and log loss, plus a calibration check since you want win probabilities) and define the baselines to beat, such as always predicting the side with more gold or a gold-difference-only model, so that "how predictable" has a measurable answer. Please also say how you will tell whether the differences between the 5, 10, and 15 minute models are real, for example with confidence intervals or bootstrapping on the test set. The data plan needs more detail on sampling: snowballing from seed players can skew the dataset toward certain ranks and regions, so state which rank tiers you will include and how you will pick seed players. Since players appear in many matches, consider whether to split by player or by time to reduce correlation between train and test games. Also estimate whether 5,000 to 10,000 matches is realistic under the Riot API rate limits, since each match needs both a match and a timeline request, and say whether you will use a development or production key. For features, define exactly which frame counts as "5 minutes" and make sure events like first blood, dragons, and towers only count if they happened before that timestamp. Many features (gold, XP, CS, role gold differences) are highly correlated, so explain how you will handle that when interpreting feature importance, for example with permutation importance or SHAP. Also note that void grubs and herald timing change between patches, so state which patches you will use. The timeline is reasonable, but Week 1 ("Finalize Proposal") has no technical tasks and there is no buffer week if data collection runs long. Finally, please proofread for small typos!
